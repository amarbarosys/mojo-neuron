# mojo-gguf

<!-- badges -->
[![ci](https://github.com/amarbaro/mojo-gguf/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/amarbaro/mojo-gguf/actions/workflows/ci.yml) [![latest release](https://img.shields.io/github/v/release/amarbaro/mojo-gguf)](https://github.com/amarbaro/mojo-gguf/releases/latest) [![license](https://img.shields.io/github/license/amarbaro/mojo-gguf)](https://github.com/amarbaro/mojo-gguf/blob/main/LICENSE)
<!-- /badges -->


GGUF tools in Mojo that write the bytes llama.cpp's own tools write: a GGUF reader and writer, the four gguf-py
scripts (`dump`, `hash`, `set-metadata`, `convert-endian`), the Qwen2 safetensors-to-GGUF converter, the LoRA and
legacy-GGML converters, eight `llama-quantize --pure` types and a dequantizer for 19 types. Every command is
compared with llama.cpp pinned at `1744c6bde`: converter and quantizer outputs are byte-identical on
Qwen2.5-0.5B-Instruct, dequantized rows are bit-equal to `ggml`'s `to_float`. Linux x86-64, CPU only.

```mojo
from ggufx import Gguf

def main() raises:
    var g = Gguf("model.gguf")                       # header and tensor table only, no tensor data is read
    print(g.summary())                               # kv 22 tensors 11 alignment 32 data_offset 1472
    print("arch present:", g.find("general.architecture") >= 0)
```

```
scripts/deps.sh                                                              # mojo-uregex into lib/, pinned
mojo build -I src -I lib src/hf2gguf.mojo -o hf2gguf
./hf2gguf Qwen2.5-0.5B-Instruct --outfile qwen.bf16.gguf --outtype bf16      # 0.26 s, same bytes as the script
mojo build -I src -I lib src/quantize.mojo -o quantize
./quantize --pure qwen.bf16.gguf qwen.q4_k.gguf Q4_K                         # same bytes as llama-quantize --pure
```

## Install

Requires Mojo 1.2 (`uv sync` installs it) and Linux x86-64, no linker flags. The tokenizer converter imports
[mojo-uregex](https://github.com/amarbaro/mojo-uregex): `scripts/deps.sh` fetches it into `lib/`, pinned to a commit.

| Way | Command |
|---|---|
| A command | `mojo build -I path/to/mojo-gguf/src -I path/to/mojo-gguf/lib path/to/mojo-gguf/src/<command>.mojo -o <command>` |
| The library | `mojo build -I path/to/mojo-gguf/src app.mojo`, then `from ggufx import Gguf` |
| Vendor | copy `src/ggufx/` into your project |

## What you get

| Command | Replaces | Scope |
|---|---|---|
| `gguf-rewrite` | `gguf_new_metadata.py` (`--name`, `--remove`) | GGUF v3 little-endian reader and writer; no edit gives the input's bytes back |
| `gguf-tool dump\|hash\|set-metadata\|convert-endian` | the four gguf-py scripts | same argv, stdout, exit code and written bytes |
| `hf2gguf` | `convert_hf_to_gguf.py` | Qwen2 (`Qwen2ForCausalLM`, `Qwen2Model`), `--outtype bf16\|q8_0` |
| `quantize --pure` | `llama-quantize --pure` | `Q8_0 Q4_0 Q4_K Q6_K Q2_K Q2_0 TQ1_0 TQ2_0` |
| `gguf-dequant` | `to_float` in `ggml-quants.c` | 19 types: F32 F16 BF16 Q4_0 Q4_1 Q5_0 Q8_0 Q2_K Q3_K Q4_K Q5_K Q6_K IQ2_XXS IQ1_S IQ1_M IQ4_NL IQ4_XS TQ1_0 Q2_0 |
| `lora2gguf` | `convert_lora_to_gguf.py` | PEFT adapters on Qwen2 bases, `--outtype f32\|f16\|bf16\|q8_0` |
| `ggml2gguf` | `convert_llama_ggml_to_gguf.py` | GGML, GGMF v1, GGJT v1 to v3 |
| `hf-update` | the check in `convert_hf_to_gguf_update.py` | pre-tokenizer fingerprint of a local `tokenizer.json`, no Python |

The generated tables (`src/ggufx/consts.mojo`, `tensor_map.mojo`, `grids.mojo`) come from gguf-py and `ggml-common.h`
through `tools/gen-tables.py` and `tools/gen-grids.sh`, and a gate fails when they drift. Commands and library calls
are in [docs/api.md](docs/api.md); which gate checks what, where it runs and its last receipt is in
[docs/gates.md](docs/gates.md).

## Performance

One run each of the gates' own timing lines, Ryzen 7 7800X3D (16 threads), Linux, a machine that was running other
jobs. The oracle column is llama.cpp's tool on the same input. Receipts: [docs/receipts/](docs/receipts/).

| Task (Qwen2.5-0.5B-Instruct) | mojo-gguf | llama.cpp tool | Receipt |
|---|---|---|---|
| `hf2gguf` bf16, 994 MB out | 0.26 s, 33 MiB peak RSS | `convert_hf_to_gguf.py` 12.55 s, 2252 MiB | `u3.txt` |
| `hf2gguf` q8_0 | 0.34 s, 33 MiB | 6.77 s, 2051 MiB | `u3.txt` |
| `quantize --pure` Q8_0 | 0.82 s, 49 MiB | `llama-quantize` 1.06 s, 1002 MiB | `u4.txt` |
| `quantize --pure` Q4_K | 0.71 s, 43 MiB | 1.29 s, 954 MiB | `u4.txt` |
| `quantize --pure` Q2_K | 0.61 s, 41 MiB | 1.17 s, 938 MiB | `u4.txt` |
| `lora2gguf`, 2 adapters x 3 out types | 0.01 to 0.04 s, 16 to 17 MiB | `convert_lora_to_gguf.py` 3.2 to 3.6 s, 1184 to 1185 MiB | `u7.txt` |
| `gguf-rewrite`, 994 MB bf16 file | 0.16 s, 13 MiB | | `u1.txt` |

Tensors are streamed through fixed buffers and consumed source pages are handed back, which is where the memory
difference comes from. The other quantizer types are in `u4.txt`: 0.5 to 0.9 s against 0.8 to 1.3 s for
`llama-quantize`.

## Limits

- Scope of "byte-identical": the Qwen2.5-0.5B-Instruct outputs of the converter and quantizer gates, the synthetic
  adapters and legacy files in the gates, and gguf-py-written fixtures. It is not a proof for every model or every
  input.
- `hf2gguf` and `lora2gguf` convert Qwen2 only. Other architectures, rope scaling, MoE keys, `head_dim`, source
  dtypes other than BF16, F16 and F32, sentence-transformers pooling, named chat templates and tokenizers without
  `tokenizer.json` are a `FAIL`, never a guess.
- `quantize` implements `--pure` only (every weight gets one type, with llama-quantize's block-size fallbacks). No
  mixed recipe such as `Q4_K_M`, no importance matrices, no types beyond the eight.
- `gguf-dequant` covers the 19 types above; any other (Q5_1, TQ2_0, IQ2_XS, IQ3_S, MXFP4 and more) is a `FAIL`.
- `ggml2gguf` refuses a GGJT Q8_0 input because the script does, and does not support `--model-metadata-dir` or
  `--vocab-dir`.
- The gates cover GGUF v3 little-endian inputs and `convert-endian ... big`.
- CI runs on synthetic fixtures against the pinned llama.cpp's Python. The converter, quantizer, dequant and LoRA
  gates need a llama.cpp build, Python with torch and the Qwen2.5-0.5B model, so they run locally
  (`scripts/oracle-gates.sh`), not on a hosted runner. The GPU is not used.
- `gguf-tool` does not include the GUI editor of gguf-py.
# mojo-json

<!-- badges -->
[![ci](https://github.com/amarbaro/mojo-json/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/amarbaro/mojo-json/actions/workflows/ci.yml) [![latest release](https://img.shields.io/github/v/release/amarbaro/mojo-json)](https://github.com/amarbaro/mojo-json/releases/latest) [![license](https://img.shields.io/github/license/amarbaro/mojo-json)](https://github.com/amarbaro/mojo-json/blob/main/LICENSE)
<!-- /badges -->

<!-- install -->
Install: `pixi add mojo-json` once published. For now: `git clone https://github.com/amarbaro/mojo-json`, then `mojo run -I mojo-json/src app.mojo`.

```mojo
from json import Json, parse


def main() raises:
    var doc = parse('{"name": "gpu", "pids": [1, 2], "load": 0.5}')
    print(doc.text("name"), doc.get("pids").len(), doc.opt_f("load").value())

    var out = Json.object()
    out.set("ok", Json.of(True))
    out.set("n", Json.of(3))
    var list = Json.array()
    list.push(Json.of("a"))
    out.set("items", list)
    print(out.dumps())  # {"ok":true,"n":3,"items":["a"]}
    print(out.dumps(False))  # {"ok": true, "n": 3, "items": ["a"]}, Python's default layout
```
<!-- /install -->

JSON for Mojo that behaves like Python's `json`: the int/float distinction, key order, and
`json.dumps` output byte for byte. The parser is strict RFC 8259 (JSONTestSuite: 95 of 95
`y_` accepted with values identical to Python's, 188 of 188 `n_` rejected), the writer is
checked against `json.dumps` on generated files in four layouts, and a parsed document is two
buffers with no allocation per value.

Requires Mojo 1.2. The only libc calls are `strtod` and `snprintf`, so no linker flags.

## What you get

- `parse(String)` and `parse(Span[UInt8])`: strict RFC 8259 with `json: <what> at byte N`
  errors. No `NaN`, no trailing commas, no lone surrogates, UTF-8 checked, nesting capped at
  1000.
- `Json`: seven kinds, accessors (`get`, `at`, `text`, `opt_f`, `opt_s`, `int`, `num`,
  `truthy`, ...), builders (`Json.of`, `array`, `object`, `push`, `set`).
- `dumps(compact, indent)`: `json.dumps(ensure_ascii=True)` byte for byte, including float
  `repr`, `\u007f`, surrogate pairs and `indent=`.
- Integers past Int64 become floats, rounded as Python's `float(int)` rounds.

The API is in [docs/api.md](docs/api.md). The memory and speed design is in
[docs/design.md](docs/design.md).

## Performance

`tests/bench.mojo` against `tools/bench_oracle.py` (Python's C-accelerated `json`) and against
the code this library replaced: 20 passes over a 4.6 MB document of 20,000 records (about
500,000 values), three runs each.

| | parse | dumps (compact) | peak RSS |
|---|---|---|---|
| Python `json` | 734 to 763 ms | 491 to 498 ms | 45.4 MB / 54.2 MB |
| previous Mojo implementation | 1,413 ms | 1,081 ms | 130 MB / 102 MB |
| mojo-json | 199 to 206 ms | 298 to 317 ms | 45.3 to 45.7 MB / 45.2 to 45.7 MB |

The memory is the document itself: the file bytes, a 32-byte node per value, one text buffer.

## Limits

- `get` and `at` copy a subtree and `at(i)` is O(i): read scalars with `text`, `opt_f`,
  `opt_s`, and keep a nested value instead of calling `get` again.
- No streaming, no `object_hook`, no big integers, no `NaN` or `Infinity` (read or written
  by a parsed document; `dumps` still prints them for a `Float64` you put in yourself, as
  Python does).
- Duplicate keys are kept, in order; `get` returns the first.
- A hostile document of nested `[` stops at depth 1000 with an error; nothing else limits
  its size.
- Strings are decoded as they are parsed, so `str()` and `text()` copy.
# mojo-imkit

<!-- badges -->
[![ci](https://github.com/amarbaro/mojo-imkit/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/amarbaro/mojo-imkit/actions/workflows/ci.yml) [![latest release](https://img.shields.io/github/v/release/amarbaro/mojo-imkit)](https://github.com/amarbaro/mojo-imkit/releases/latest) [![license](https://img.shields.io/github/license/amarbaro/mojo-imkit)](https://github.com/amarbaro/mojo-imkit/blob/main/LICENSE)
<!-- /badges -->

An immediate-mode GUI for Mojo apps, drawn by the GPU. It takes the idea behind Dear ImGui and imgui-bundle (widgets
are function calls made every frame, no retained widget tree) and builds it in Mojo around a GPU app's own frame:
widgets append to one flat draw list, one `compose` kernel turns that list into an RGBA layer, and the window blends
the layer over the app's picture. No Python UI process, no C++ library, no bundled windowing: the system's SDL3 and
FreeType are called through Mojo's FFI.


## Modules

| module | what it does |
|---|---|
| `imkit.window` | SDL3 window, vsync, letterboxed streaming texture; `poll() -> Input` (mouse, wheel, buttons, keys, typed text, quit), `text_input(on)`, `present(frame, ui)`, `push()` synthetic mouse, key and text events for scripted checks |
| `imkit.layer` | `Layer(ctx, ui)`: the GPU side on your DeviceContext (buffers, atlas from `ui`, image sources `src`); `render(ui)` after `Ui.finish()` uploads only what the frame used and fills the pinned `pixels`; `set_image(px, w, h)` copies one picture to the image pool (`-DUI_IMG=` sizes it) |
| `imkit.font` | glyph atlas from a TrueType font (ASCII 32-126, a few pixel sizes, alpha8), built once at start |
| `imkit.ui` | `Ui`: `begin(input)`, `panel`, `button`, `icon`, `bar`, `spark`, `text`, `field` (single-line text box), `rect`, `line`, `tri`, `image`, `finish()`; the `compose` kernel; a dark theme |

## Use

```mojo
from imkit.window import Window
from imkit.font import Font
from imkit.layer import Layer
from imkit import ui as im
from max.gpu.host import DeviceContext

var win = Window("App", W, H, im.UW, im.UH)          # W x H: your frame; UW x UH: the UI layer
var u = im.Ui(Font("/usr/share/fonts/TTF/Roboto-Medium.ttf", [13, 16, 22]))
var layer = Layer(DeviceContext(), u)                # once, on your app's context: buffers, the atlas from u
while True:
    var inp = win.poll()
    if inp.quit:
        break
    u.begin(inp)
    u.panel(20, 16, 400, 92, "Run")
    if u.icon(1, 1):                                  # 0 play, 1 pause, 2 step, 3 stop
        pause()
    u.finish()                                        # bins the commands into 16 x 16 tiles
    layer.render(u)                                   # uploads what the frame used, composes, copies back; synchronizes
    win.present(frame_ptr, Int(layer.pixels.unsafe_ptr()))
```

## Install

Mojo 1.2 and MAX 26.7 from `uv sync`; system `libSDL3.so.0` (3.4) and `libfreetype.so.6` (2.14); a TrueType font
(Roboto Medium by default, `IMKIT_FONT` overrides). Use it with `mojo build -I path/to/mojo-imkit/src app.mojo` or
`mojo precompile src/imkit -o imkit.mojoc`. A headless example: `examples/quickstart.mojo`.

## Verified

`scripts/ci.sh` (no GPU, no display): precompile, build of every test, `font_test` (glyph atlas), `ui_cpu_test` (click =
press then release, tile bins, overflow drops counted, text fields, image fit; a mutant of the click rule fails it) and the quickstart.
`scripts/mutants.sh` breaks the field maximum and the text join of `Input.merge` in a copy of `src`; each must fail its test.
`scripts/local_gate.sh` (run locally, GitHub runners have no GPU or display): `ui_test` composes on the GPU and checks
pixels, `window_test` opens a real SDL3 window. Last local run on an RX 7900 XTX (gfx1100), KDE Wayland: `PASS ui_test`.

## Performance

RX 7900 XTX, 1280 x 720, 150 commands, one run of `ui_test`: compose 25.8 us per launch, render 194 us per frame
including the 3.7 MB layer copy back. Buffers (allocated once): draw list 128 KB, tile bins 64 KB, atlas 128 KB on the
card. An earlier run measured compose at 17.7 us; the number moves with GPU clocks and load. Design and budgets:
[docs/design.md](docs/design.md), API: [docs/api.md](docs/api.md).

## Limits

- ASCII text only, no shaping; no docking, axes plots, sliders, menus or DPI scaling. `Ui.field` is one ASCII line (append, Backspace; no cursor movement, selection, paste or key repeat).
- Needs a GPU MAX supports for `Layer`; only gfx1100 was tested. Struct offsets are those of SDL 3.4 and FreeType 2.14.
- Key scancodes below 128 only. `Audio` (mono float playback) has no automated check.
- CI covers the CPU side only; the compose kernel and the window are checked locally.
