# mojo-neuron plan

Find, rank and steer single MLP neurons of GGUF models on mojo-baro, and export them as llama.cpp
control vectors. About 600 LOC of Mojo, because GGUF reading, dequantization and the GPU forward
already exist in our libraries. Not a trainer. MoE experts are out of scope for now.

Ideas come from gguf-neuron-explorer (`gne`, MIT) and neuron-explorer (MIT). Written clean-room in
Mojo; no code copied.

## Reuse (surveyed 2026-11-04)

| need | reuse | state |
|---|---|---|
| GGUF read, dequant of all quant types | mojo-gguf `gguf.model.Gguf`, `gguf.dequant.deq_rows` | done |
| thread pool | mojo-gguf `gguf.par.parallelize` | done |
| GPU forward, 6 archs | mojo-baro `serve/spark.mojo` (llama, qwen2, granite), `serve/engine.mojo` (qwen35) | done |
| per-layer residual hook | baro branch `ablate`: `BARO_DUMP_LAYERS`, `BARO_ABLATE` (host-side, spark only) | partial |
| logits dump | baro `BARO_DUMP_LOGITS` | done |
| TPE, KL | mojo-ablate `src/tpe.mojo`, `src/kl.mojo` | done |
| UI | gne `gne/ui/static` (vanilla JS) served as static files | later |

## Steps

Each step lands as its own commit, with its gate written first.

| # | item | LOC | performance target | oracle |
|---|---|---|---|---|
| 1 | `lens`: logit lens for every neuron of a layer, CPU | S | Qwen2.5-0.5B layer in < 5 s | f64 brute force on sampled neurons, plus a mutant |
| 2 | baro `BARO_STEER`: add one f32 vector per layer into X after the FFN, GPU kernel, no host sync | S | decode cost < 1 % | zero vector byte-identical; greedy equals llama.cpp `--control-vector` |
| 3 | `cvec`: write `.cvec.gguf` (`direction.L`, arch `controlvector`) from a recipe `L:N:dose,...` | S | n/a | llama-cli loads it; greedy equals step 2 |
| 4 | `sweep`: one resident baro process runs neurons x doses x prompts | M | engine startup paid once | same tokens as one-shot runs |
| 5 | `rank`: word-cluster mass against random-direction controls | S | < 1 s per layer, host-side | hand-built rollout golden |
| 6 | serve the gne UI and an MCP server over steps 1 to 5 | M | n/a | UI looked at in the browser |

Step 2 is measured first. If the hook costs more than 1 % of decode, it moves into the FFN down
gemv epilogue.

## Lens math

For neuron n of layer L: g = unit(W_down[:, n]) * output_norm_weight, logits = W_U g. Keep the top
and bottom k tokens. One pass over W_U per layer: each vocab row is dotted with every neuron while
the neuron block stays in L3.

## Gates

`scripts/check.sh` runs every test capped with
`systemd-run --user --scope -p MemoryMax=4G -- timeout 300`. GPU work goes through `gpu-wait run`.

# Rules

`what broke -> the rule`

- `lens` returned the same special tokens for every neuron after the ggufx sync -> mojo-gguf v0.2.1 had lost the heap thread context fix (deq_rows wrote zeros, output_norm read as 0). A model output identical for all units: dump the raw z and the norm weights before suspecting the math. Gate `scripts/check.sh` runs lens on real weights, so it catches this.
- A parameter or field named `out` did not parse (twice) -> `out` is a Mojo keyword: use `nout`, `root`, `dir`.
- Brain mutant query "zzqxjv neuron layer 12 qwen2.5" still found the neuron through shared words -> a mutant query must carry only the discriminating token.
- A total sum of activations could not tell my reversed-token mutant apart (sums cancel) -> compare the per-element head and tail values llama.cpp prints, not the tensor sum.
- llama.cpp prunes the last layer to the output positions and elides tokens when a prompt has more than 6 tokens -> the oracle uses prompts of at most 6 tokens and skips the last layer.
- imkit font atlas is ASCII 32 to 126 and the draw list holds 4096 commands (one per glyph) -> the app sanitizes every token to ASCII and budgets text per frame.
- MCP server passed a pipe gate but failed under Claude Code ("Connection closed"): `input()` returned EOF after the first line and `/dev/stdin` cannot be opened when the client gives a socket -> read fd 0 with `read(2)`, and gate it with a real client (`tests/mcp_client.sh`), not only a pipe.
# App

`scripts/build-app.sh` then `.work/app` (store: `MNEURON_DIR`, default the shared `.work/neurons` of the main repo).
Views: **map** (layers x 40 neuron buckets, colour = best lens score, click a cell), **list** (ranked by lens score or sweep rank,
token search over the lens, page buttons or wheel), **neuron** (lens, connections up/down clickable, fires on your text, recipe buttons,
brain note, dossier file, steered chat panel). Every button runs a call from `src/mneuron/calls.mojo`, the same code as the CLI and MCP.

The steered chat shows rollouts from `<layer>.sweep.jsonl` for the neuron (engine lane). Live generation is a stub: UNVERIFIED until the
engine's sweep is wired in.

Script mode for checks: `MNEURON_SCRIPT=file .work/app` with lines `frame`, `wait N`, `click X Y`, `text S`, `wheel D`, `shot PNG`;
at exit it prints one `STATE ...` line. `tests/app.sh` is the gate, `tests/app_script.txt` the script. Needs a display and the GPU
(imkit composes the UI on the GPU; not a compute job).

# mojo-neuron

Find, rank and steer single MLP neurons of GGUF models, in Mojo, on mojo-baro. Plan: `docs/plan.md`.

## lens

Logit lens of every neuron of one layer, on CPU:

    lens MODEL.gguf LAYER K          # one line per neuron: n, top K tokens, bottom K tokens (sep U+241F)
    lens MODEL.gguf LAYER K CHECK    # f64 brute-force golden on CHECK sampled neurons + neighbour mutant

Qwen2.5-0.5B Q4_K_M, layer 12 (4864 neurons x 151936 tokens): 4.2 s on a 7800X3D.

Gate: `scripts/check.sh` (qwen2 and llama). Build needs mojo-gguf at or after `f56d2a3`.

Ideas from gguf-neuron-explorer and neuron-explorer (both MIT); no code copied.
