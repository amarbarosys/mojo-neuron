## VERDICT

C0, C1, C2, C3, C4, E2 and E3 are built, each gate passed on its own run, and `scripts/check.sh` passes on the merged tree (f36e610).
Four things differ from what the plan text promised:

1. **C2 prereg bar 5 MISSED.** The negated dial should give cosine < 0 against the original delta; it gave +0.005. Bars 1 to 4 held. The logit response is not linear at these doses, so the mutant is rejected by rel err 1.078 instead (annotation in `docs/prereg-C2.md`, bars unchanged).
2. **C1 strips channels, not neurons or features.** The capture holds residual-space rows. A click opens a channel dossier (the channel over all tokens, its strongest tokens), not a neuron dossier. Neuron activations need the FFN weights on top of the captured input; features need B1's transcoder. Neither is wired.
3. **I heard and looked at nothing.** Sound is checked by FFT and a golden hash, images by size, spread and distinctness. Whether either is good is the maintainer's call.
4. **E1 (steer passthrough) is not in the server yet.** `nx chat --steer` sends the field and the server ignores it. The chat gate proves the request body, not an effect.

The commits are not one per item. The hunks of C1 to C4 interleave in `src/app.mojo` and `src/mneuron/calls.mojo`, and the intermediate states would not build, so they are one commit (1ded0bd).

## Deviations and what is missing

- `tools/baro serve` could not be used. Its engine rebuild from the sources embedded in the GGUF fails (`read` signature clash in `serve_proto.mojo`, log `~/.cache/baro/qwen35-c19706672fb25b4a/build.log`). `scripts/agents/baro-serve.sh` runs the Rust server directly on lane A's `engine-9b` and the e11b Qwythos-9B pack. Lane baro should know the blessed launcher is broken for qwen35 on this toolchain.
- The agent CLIs run least-privilege: qwen plan mode, omp `--tools read`, hermes file toolset without `--yolo`. My first draft used `--yolo` and the auto-mode classifier refused it, which was right for a local model.
- A steer profile for the agent CLIs is refused: they cannot add the per-request `steer` field and baro has no server-side default.
- The app window does not show the C4 picture (file and status line only). "draw image" is not exercised by a gate; the `image` call is, with two turns.
- "play capture" is gated in render mode only. The SDL audio device path was not run.
- The C2 live blend is a lens preview, not an engine generation of the blend. `nx live` still handles one neuron.
- The C1 append test uses a synthetic growing capture; the equality test uses a real engine capture. A live engine generating while the app tails it was not run.
- C2b is preregistered only.
- A smoke call of mine wrote `dial.f32` and `dial.cvec.gguf` into the shared main store (the shell lacked `MNEURON_DIR`). I deleted both files; one `cvec` rlog line from that call stays in the shared research log.

## Mistakes (all in `docs/rules.md`)

A stale binary passed a failed build. `[ x = +* ]` does not glob. A byte-equality check compared the bf16 file to the Q4_K_M store. The slider range in rho units wiped the text. A package named like the build root was not found. The `out` keyword again. gpu-wait spawns with its own PATH. PIL was missing in a lane venv. A byte slice past the end aborts. Rlog's model argument is a file path. A launcher declared a queued job dead. A failing blessed launcher was not a reason to swap model files. `--yolo` was refused.
