## A1: capture

Qwythos runs in `engine.mojo`/`window.mojo`, so the op lives there (the boss agreed). A first gate run failed because the replay window fed four prompt rows per step; capture now forces one position per step and the engine
refuses a step that advances more. Gate (13-token prompt, 76 records): residual bit-equal to `f16(BARO_DUMP)` at the last prompt position for layers 0, 16 and 31, `y = r - mid` within 1e-2, `x` rms sane, shifted-layer mutant rejected.

## A2: ablation scan, and what it found

The tool (`scan`) zeroes each listed neuron of one layer inside one resident engine over 64 prompts and ranks mean KL and mean NLL change of the target token. A full layer (12288 neurons) would take about 12.6 h at the measured
57 ms per 10-token request, so scans take a neuron list.

- Run 1 (prereg `docs/prereg-a2.md`) FAILED its own mutant bar: its 1e-6 absolute tolerance was larger than the spread of the scores (all 24 neurons scored 7.7e-6 to 1.2e-5). The single-neuron re-runs were in fact bit-identical to the batch. The failure stays reported; the tolerance changed only through a new prereg.
- Falsifier: damage should grow like (k-1)^2 with the gain. It did not near zero: neuron 3 scores 7.8e-6 at gain 0, 9.0e-6 at -1, 1.9e-5 at 10, 1.4e-3 at 100. Gain 0.999 scores exactly 0.0 (bf16 rounds the change away), gain 0.99 already scores 7e-6.
  Any change that survives bf16 rounding re-rolls the rounding downstream and lands on a noise floor of about 7e-6 to 1.2e-5, whatever its size.
- A2b (`docs/prereg-a2b.md`, one run): 16 neurons, floor (median of the gain-0.99 pass) 7.671e-6, kl 7.7e-6 to 1.2e-5, none detectable (excess over twice the floor). That is a statement about these 16 neurons on these prompts.
  `scan ctl=0.99` now ranks by the excess over the floor pass and prints its ablation mode and metric (KL plus target NLL, zero ablation, clean prompts only).
- Not built: the direct-effect pre-rank from the papers synthesis (prereg `docs/prereg-papers-fold.md`, bars P-A to P-C written, no code yet).

## A3: surgery

`surgery ... op=zero` zeroes the neuron's `ffn_up` row: all-zero blocks dequantize to 0 in every ggml type, so the activation is exactly 0 and only that row's bytes change (a reflink copy, 2304 bytes touched in the gate).
Zeroing the down column of a K-quant cannot be exact (a block has no exact zero; 0.0122 left against 0.0698 on the 0.5B test), so `via=down` and scale/replace/add print the residual instead of claiming equality.
Gate: the engine pack baked from the surgery GGUF gives the same logits as engine `gain 16:1031:0` on the original pack (max diff 0.000); the unablated run differs by 3.5e-2; llama.cpp loads the file and generates.
The engine reads a pack baked from the Q4_0-pure GGUF, not the Q4_K_M, so a surgery file needs `engine-pack.py` before the engine can serve it. `nx surgery` and `nx scan` call the tool binaries.
